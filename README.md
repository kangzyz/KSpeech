# KSpeech

[English](README.en.md) · 简体中文

![KSpeech：Windows 本地实时语音字幕](imgs/banner.png)

> 把电脑正在播放的声音、麦克风、甚至指定某一个程序的声音，实时转成**带标点**的字幕浮在屏幕上。识别全程在本机完成，音频不出电脑。

KSpeech 是 [TMSpeech](https://github.com/jxlpzqc/TMSpeech) 的重写版本：字幕、设置、历史、音频采集、任务调度和资源管理全部用 **Go + Wails 3 + Vue 3** 重新实现，并在此之上补齐了自动标点、AI 助手和完整的发布链路。产物是一个约 12 MB 的 EXE 加几个原生推理 DLL，**不需要 .NET 运行时**。

关键词：语音转文字，实时字幕，会议语音识别，悬浮字幕，识别历史记录，实时会议纪要，实时问答

## 这一版重写和新增了什么

上游是 .NET + Avalonia 的实现，这一版把主程序整体换成了 Go + Wails 3 + Vue 3，并在重写过程中补上了下面这些：

- **自动标点**。流式模型只吐裸文本，KSpeech 在每句定稿后补句号或问号；愿意多花一点内存就挂上 CT-Transformer 标点模型，句子中间也会断句加逗号。
- **字幕是一条可以往回翻的消息流**。说完的每一句像聊天记录一样堆在滚动窗口里，正在说的那句吊在最下面；往上翻会停住不再被新句子拽走，一个「回到最新」按钮送你回去。
- **AI 助手**（可选，默认关闭）。滚动汇总关键要点、自动回答字幕里出现的问句，还能声明服务商自己的联网搜索。
- **按进程采集**。除了系统全局回环和麦克风，可以只录指定 PID 及其子进程的声音（Application Loopback）。
- **一个窗口装下全部**。左栏实时字幕与历史、中栏 AI 要点、右栏 AI 对话，三栏可以拖动改宽窄、可以单独收起；窗口默认不大、随手拉伸，锁定后位置固定但内容照样能翻。
- **多路音频，分得清谁在说**。麦克风和系统声音可以同时录：每一路各跑一份识别，消息流按说话人上色带名字前缀，可以只看某一个人，AI 助手也知道哪句是你说的。
- **事务化的模型安装**。SHA-256 校验、下载与解压体积上限、防路径逃逸与符号链接、暂存后原子切换、失败整体回滚，索引强制 HTTPS。
- **配置容错**。配置写坏或写到一半断电时，先尝试恢复上一版本，不行就隔离坏文件以默认值启动，并在界面说明发生了什么。
- **完整的发布链路**。原子发布脚本 + Inno Setup 安装程序（按用户安装、不需要管理员权限、自动补装 WebView2），图标与安装配图由脚本从原图统一导出。
- **近 200 个 Go 测试**覆盖任务调度、配置存储、资源事务、三个识别器和 AI 助手，`go vet` 干净；发布构建会把默认与原生两套标签的测试都跑一遍。

保持不变的部分：仍然基于 [sherpa-onnx](https://github.com/k2-fsa/sherpa-onnx/) 的流式模型，仍然沿用上游的扁平配置键、插件键转义规则和外部命令识别协议，旧的模型资源可以直接拿来用。

## 你可以用它做什么

- 一边开会一边干别的：被点名时往回翻两屏就能补上刚才的内容，开了 AI 助手连要点和现成答案都在同一个窗口里。
- 给没有字幕的网课、直播、外语视频加一层实时字幕，只录那个播放器的声音也行。
- 边说边留记录：字幕可搜索、可复制，也可以自动写进日志文件夹。

## 功能

- **透明置顶的三栏主窗口**：无边框、四边可拖动缩放、位置与大小自动记忆；可以隐藏到托盘，可以锁定位置（锁定只固定窗口，字幕照样能翻、AI 照样能问）。
- **三种音频源，可同时录多路**：默认播放设备全局回环（录内音，播放设备静音时照样捕获）、麦克风、指定进程及其子进程（需要 Windows 10 build 20348+）。每一路都能起名字（默认「我」「其他人」），消息流按说话人上色并可筛选。
- **三种识别引擎**：Sherpa ONNX（流式，CPU）、Sherpa NCNN（兼容旧七文件模型）、外部命令识别器（由你的程序自己采音并输出字幕）。
- **自动标点**：默认规则实现零依赖，句末自动补句号或问号；也可以挂上 sherpa-onnx 的中英 CT-Transformer 标点模型，让句子中间也断句加逗号。
- **自带热词表与数字规范化**：随包附一份 395 条的中英热词表（轨道交通、AI、编程语言、科技术语）和官方 ITN 规则文件，装完即用——专有名词更准，「二零二五」自动写成 2025。
- **可回翻的字幕流**：本次运行的完整字幕留在左栏，可搜索高亮、可按说话人筛选、可整体或逐条复制，可选写入日志文件夹。
- **AI 助手（可选，默认关闭）**：填自己的 OpenAI 兼容接口，中栏滚动汇总关键要点，右栏自动回答字幕里的问句、也能手动追问。
- **模型市场**：下载、更新、移除模型，全程校验与回滚。
- **通知**：敏感词提醒与错误通知，走 Windows 原生通知。
- **深浅双主题**：界面跟随系统；字幕的字体、字号、颜色、阴影、对齐，以及面板的背景色与悬停高亮都能自定义。选的字体颜色在当前主题的面板上看不清时，字幕会自动改用主题自带的颜色，并在设置里说明原因。

**主窗口**：一个无边框的毛玻璃面板，浮在其他窗口之上。顶上一条控制栏（开始 / 暂停 / 停止、计时、收起要点栏、收起对话栏、锁定、隐藏、设置），下面三栏：

![主窗口](imgs/console.png)

- **左栏 实时字幕**：说完的每一句像聊天记录一样往下堆，正在说的那句吊在最下面并带「正在识别」标记。往上翻会停住不再被新句子拽走，右下角出现「回到最新」。搜索按钮就地筛选并高亮，多路音频时上面多一排说话人筛选（上图的「我」和「其他人」分别来自麦克风和系统声音），`Ctrl+A` 全选整条字幕。句末的句号和问号是整句说完之后自动补上的。
- **中栏 要点总结**：AI 助手按时间累积的关键要点，默认每 90 秒一次。
- **右栏 AI 对话**：字幕里出现问句会自动作答，底部输入框也能随时追问。

三栏之间的分隔条可以拖动改宽窄，中栏和右栏都能从控制栏收起；窗口拉窄到装不下时会自动折叠，拉宽再自己回来。把两栏都收掉、窗口拉小，就退回成一个纯粹的浮动字幕框：

**设置**：左侧分类导航 + 右侧卡片式分组，改动即时保存并回显“已保存”。字幕的字体与配色在「外观」页调，引擎、模型、热词和标点方式在「识别引擎」页。

**模型市场**：在「资源」页下载、更新、移除模型，带 SHA-256 校验、安全解压与失败回滚。

## 安装与使用

从 [Release](https://github.com/kangzyz/KSpeech/releases) 页面下载：

- `KSpeech-<版本>-win-x64-setup.exe`：安装程序，默认按用户安装到 `%LOCALAPPDATA%\Programs\KSpeech`，不需要管理员权限，缺少 WebView2 运行时会自动补装。
- `KSpeech-<版本>-win-x64.zip`：便携包，解压后直接运行 `KSpeech.exe`。

两个包都**不含语音模型**：首次启动后到「设置 → 资源」下载一个流式模型，再到「设置 → 识别引擎」里选中它。首次安装默认**不会**自动开始识别，避免没有模型时启动即失败；配置好之后可以在「设置 → 通用」里打开“启动后自动开始识别”。

运行环境：Windows 10 2004（10.0.19041）及以上，x64。指定进程采集另需 Windows 10 build 20348+。

## 自动标点

流式识别模型只输出裸文本，标点由 KSpeech 在**整句定稿之后**补上，识别中的临时字幕保持原样，不会边说边跳字。在「设置 → 识别引擎 → 标点符号」里切换：

| 方式 | 效果 | 代价 |
| --- | --- | --- |
| 基础规则（默认） | 句末补「。」或「？」，中英文自动切换全角半角，已带标点不重复加 | 无，不用下载任何东西 |
| 标点模型 | 句子中间也断句加逗号 | 需要 sherpa-onnx 中英 CT-Transformer 标点模型，多占一份内存和少量 CPU |

选「标点模型」时把模型路径指向 [sherpa-onnx-punct-ct-transformer-zh-en-vocab272727-2024-04-12](https://k2-fsa.github.io/sherpa/onnx/punctuation/pretrained_models.html) 解压后的 `model.onnx`。模型读不出来时会自动退回基础规则并在界面提示，不会中断这次识别。

嫌一句话太长的话，同一页的「整句最长字数」可以把强制断句的阈值调小（默认 80 字）。

## AI 助手：实时要点与提问回复

在「设置 → AI 助手」里填自己的模型接口即可开启。任何兼容 OpenAI `/chat/completions` 的服务都能用：DeepSeek、通义千问（兼容模式）、智谱、Moonshot、OpenRouter，以及本机的 Ollama、LM Studio、vLLM。

```text
API 地址：https://api.deepseek.com/v1      # 填到 /v1 为止，KSpeech 会自动补 /chat/completions
API Key ：sk-xxxxxxxx                      # 本机模型可留空
模型名称：deepseek-chat                    # 要点和回答都是短文本，小模型足够
```

填好后点「测试连接」确认通，再打开顶部的开关。开启后：

- **关键要点**：每隔一段时间（默认 90 秒，可调 15–1800 秒）把这期间说过的话浓缩成最多 3 条要点，带时间戳累积在左栏；停止识别时补一次收尾汇总。这段话没有实质信息时不产生要点。
- **实时回复**：字幕里出现问句（`？`、“吗”、“为什么”、“谁负责”、“how/why…”）时，自动带上最近 30 句上下文请求模型，给出可以直接说出口的回答；两次自动回答之间至少间隔 8 秒。也可以在底部手动追问，追问会带上之前的问答（更早的那些自动压缩成摘要），所以「再详细讲讲」接得上。
- **模型内置工具**：默认开启，回答时声明服务商自己托管的联网搜索，这样“上周那个发布会定在哪天”这类问题才查得到模型训练之后的事。工具由服务商执行并计费。
- **补充背景**：在「高级」里写上会议主题、参会人和专有名词写法，能明显减少同音字造成的误解。

服务商按 API 地址判断，认不出来时退回按模型名判断（中转网关靠这条生效）：

| 服务商 | `/chat/completions` 上的内置工具 |
| --- | --- |
| OpenAI、智谱 GLM、Kimi（Moonshot）、MiniMax | 联网搜索（`tools` 声明） |
| 通义千问（百炼）、文心一言（千帆）、腾讯混元、Google Gemini、OpenRouter | 联网搜索（请求参数开关） |
| DeepSeek、豆包（火山方舟）、xAI Grok、Anthropic Claude、本机模型 | 无——官方接口在这条协议上不提供托管工具 |

接口若拒绝工具声明，KSpeech 会去掉工具重试一次，回答照常返回，并在 AI 对话栏里提示这次没有联网。

关于隐私和费用：

1. **默认关闭**，关闭时不会发起任何模型请求，识别本身始终在本机完成。
2. 开启后发出去的只有**已完成的整句字幕文本**，识别中的临时结果和音频都不外发。
3. 开着内置工具时，服务商可能拿你的问题去搜索；不希望如此就在「模型内置工具」里关掉。
4. API Key 明文存放在 `%APPDATA%\KSpeech\config.json`，建议用额度受限的专用 Key。
5. 公网地址必须是 `https`，`http` 只放行本机与内网（Ollama 这类本地服务）。
6. 费用取决于说话量：汇总间隔越短、上下文句数越多，token 消耗越大。请求失败会在 AI 对话栏里报错并等下一个间隔重试，不会反复重试。

## 音频源与识别引擎

三种音频源统一输出 `float32 / 16 kHz / 单声道`：全局回环录的是系统混音，把播放设备静音也照录；指定进程走 Windows 的 Application Loopback，能单独抓某个播放器或会议软件，连它拉起的子进程一起。

「设置 → 音频源」里可以同时打开多路，最典型的是**麦克风 + 系统声音**：麦克风录你自己，系统声音录会议里的其他人。每一路有自己的说话人名字（默认「我」和「其他人」，最多 12 个字，留空就不加前缀），消息流按说话人上色、每句前面带名字，可以只看某一个人，日志文件写成 `15:04:05 我: ……`。两点要知道：

- 每一路都会**单独跑一份识别引擎**，内存和 CPU 大致按路数翻倍；机器跟不上时某一路会丢掉一小段声音并提示一次，识别不会因此中断。
- **建议戴耳机**。外放时麦克风会把对方的声音再录一遍，同一句话会被记成两个人说的。

内置引擎里，**Sherpa ONNX** 是主力（流式 Zipformer-transducer，CPU），设置页可以调解码方式、热词文件与权重、ITN 规则文件和整句最长字数；**Sherpa NCNN** 用来兼容旧的七文件模型。

### 热词与数字规范化

安装包里带两个文件，装在 KSpeech.exe 旁边，首次启动自动填进「设置 → 识别引擎」，不想要就把对应输入框清空（清空后不会被再填回来）：

- `hotwords.txt`：395 条热词，覆盖轨道交通（屏蔽门、CBTC、ATO、一号线…）、AI（大模型、RAG、TRANSFORMER、PYTORCH…）、编程语言（PYTHON、GOLANG、RUST…）和科技术语（KUBERNETES、GRPC、灰度发布…）。热词只在 `modified_beam_search` 下生效，所以新装默认就用它——比 greedy 更吃 CPU，机器紧张时直接把解码方式换回 `greedy_search`：热词随之停用，但路径会留在设置里，换回来就恢复。
- `itn_zh_number.fst`：k2-fsa 官方的中文数字规则，把「二零二五」写成 2025。

自己加词时有三条硬规则，踩了不报错、只是不生效（第一条更严重）：

1. **不能写注释**。`#` 开头的行会被当成关键词阈值去解析，直接让识别进程退出。
2. **英文必须全大写**，因为这类模型的 BPE 词表是全大写的；而且模型目录里要有 `bpe.vocab`（中英双语模型有，纯中文模型没有，后者的英文词会被跳过）。
3. **不能有阿拉伯数字和标点**。数字不在模型词表里，写「五号线」而不是「5号线」，显示成阿拉伯数字是 ITN 的活；`GPT-4`、`C++`、`CI/CD` 这种带符号的整行都会作废。

行末加 ` :3.0` 可以给单个词调权重（覆盖全局的热词权重）。改完用仓库脚本自查一遍：

```powershell
python .\scripts\check-hotwords.py .\assets\hotwords.txt "$env:APPDATA\KSpeech\plugins\<资源>\<模型目录>"
```

想保留自己的词表不被升级覆盖，把文件复制到 `%APPDATA%\KSpeech\` 再把设置里的路径指过去。

### 外部命令识别器

想用自己的识别方案时，在「设置 → 识别引擎」里选「外部命令」，KSpeech 会按你填的程序和参数拉起子进程，把它的标准输出当字幕流，同时持续排空标准错误（可选择写进日志文件；写不进去只告警，不影响识别）。

协议只有一条规则：**单个换行 = 更新当前这句，连续两个换行 = 这句说完了**。只有说完的句子才会进历史记录，所以模型可以在后面纠正前面的结果。

```text
一二
一二三四
一二三四五六七

七六五四三二一

```

仓库的 `external_recognizer/` 下有三个可以直接用的实现：`streaming-with-endpoint-detection.py`（sherpa-onnx 流式 + 端点检测）、`simulate-streaming-sense-voice.py` 和 `simulate-streaming-funasr-nano.py`（离线模型 + Silero VAD，检测到完整语音段后整段解码，因此字幕会在停顿后一次性提交）。用法与模型下载见 [external_recognizer/](external_recognizer/) 里的脚本参数说明。

几点注意：

- 子进程自己负责采音，设置里的音频源对它不生效。
- 多个参数用空格分隔，参数本身带空格（例如路径）时用双引号包起来。
- 程序是 `.bat` / `.cmd` 时会通过 `%ComSpec% /d /s /c` 启动，记得在命令前加 `@` 隐藏回显，结尾不要写 `pause`。

## 模型

模型市场的索引和模型都托管在 GitHub。国内直连经常时通时断，KSpeech 因此会跟随 Windows 的系统代理设置（「设置 → 网络和 Internet → 代理」里的手动代理），和浏览器走同一个；`HTTPS_PROXY` 之类的环境变量优先级更高。刷新超时就是没连上，已装的资源不受影响。

识别效果主要取决于模型。「设置 → 资源」里的模型市场提供 5 个 sherpa-onnx 流式识别模型（中文、英文、中英双语、法语、韩语）和 1 个中英标点模型（CT-Transformer int8，62 MB），索引托管在本仓库的 [marketplace/](marketplace/)，每个条目都带 SHA-256。标点模型装好后，在「识别引擎 → 标点方式」选「标点模型」，下面的下拉框直接选中它即可，不用手填路径。想用别的模型，可以从 [sherpa-onnx 的流式模型列表](https://k2-fsa.github.io/sherpa/onnx/pretrained_models/online-transducer/zipformer-transducer-models.html)下载后，在设置里直接指定 encoder / decoder / joiner / tokens 四个文件的路径。

| 配置文件（含 AI 助手的接口地址与 Key，明文） | `%APPDATA%\KSpeech\config.json` |
| 已下载的模型与扩展 | `%APPDATA%\KSpeech\plugins\` |
| 识别日志（默认） | `我的文档\KSpeechLogs` |

配置文件损坏或写到一半断电时，KSpeech 会先尝试恢复上一版本，实在不行就隔离坏文件、以默认值启动，并在界面上说明发生了什么，而不是直接崩掉。

## 从源码构建

环境要求：Windows 11 x64、Go 1.25+、Node.js 与 pnpm 11.16.0。Wails 固定为 `v3.0.0-beta.7`。

```powershell
pnpm --dir .\frontend install --frozen-lockfile
pnpm --dir .\frontend run build
go test .\... -count=1
go vet .\...
go build -o .\build-dev\KSpeech.exe .
```

普通 `go build` 用的是**不含原生推理**的 Sherpa stub，适合界面、配置和外部命令识别器的开发。带原生识别的生产包与安装程序（都要用 PowerShell 7）：

```powershell
.\scripts\build-windows.ps1 -Version 0.1.0 -Commit (git rev-parse --short HEAD)
.\scripts\build-installer.ps1 -Version 0.1.0
```

生产构建需要 `CGO_ENABLED=1` 与 MinGW-w64 x64 GCC，会把 sherpa-onnx / sherpa-ncnn 的 Windows DLL 及所需的 Microsoft VC++/OpenMP 运行库一并放进 `publish\`，再由 Inno Setup 6.3+ 打成 `build\installer\` 下的安装程序。图标、安装向导配图和 README 横幅由 `scripts\make-brand-assets.py` 从 `imgs\` 统一导出。更多细节见 [Develop.md](Develop.md)。
